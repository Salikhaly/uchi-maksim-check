🎓 СПИН — ведём клиента за руку

Не набор разрозненных вариантов. Один последовательный маршрут: Ситуация → Проблема → Извлечение → Наведение → СПВ → следующий шаг. Каждый следующий вопрос появляется только после предыдущего.

1. С · Ситуация

Главный вопрос: «Как сейчас ведёте учёт и контролируете магазин?»

Слушаем: чем пользуется клиент, кто отвечает, как контролирует деньги/товар/сотрудников.

Переход: когда понял текущую систему — не продаём. Переходим к поиску проблемы.

2. П · Проблема

Главный вопрос: «Где сейчас возникают сложности или что хотелось бы делать удобнее?»

Слушаем: недостачи, потеря времени, отсутствие контроля, ошибки, зависимость от сотрудников, проблемы с товаром/деньгами.

Переход: клиент назвал проблему → не предлагаем решение. Сначала выясняем, к чему она приводит.

3. И · Извлечение

Главный вопрос: «Что происходит из-за этой проблемы? К чему она приводит по деньгам, времени или контролю?»

Слушаем: последствия проблемы и её реальную цену для бизнеса.

Переход: появилась понятная цена проблемы → теперь можно спросить про желаемое состояние.

4. Н · Наведение

Главный вопрос: «Если это решить, что для вас изменится и какой результат был бы важен?»

Слушаем: что клиент хочет получить: контроль, экономию времени, меньше потерь, рост.

Переход: теперь есть связка проблема → последствия → желаемый результат. Только здесь выбираем решение.

5. СПВ — только под найденную боль

СвойствоЧто умеет решение.
ПреимуществоКак это меняет работу клиента.
ВыгодаКакой результат получает именно этот клиент.

Правило: не показываем весь функционал. Берём только ту функцию, которая закрывает проблему, которую клиент сам назвал.

6. Следующий шаг

В холодном звонке после диагностики цель — назначить встречу. На встрече маршрут продолжается: диагностика → боль → СПВ → ценность → цена/следующий шаг.

🧭 Правило перехода

Ответ клиента → понять, на каком этапе мы находимся → задать следующий вопрос.

Не выбираем случайную заготовку. Ведём разговор по цепочке: С → П → И → Н → СПВ → следующий шаг.

🧩 СПВ — отдельная страница

Здесь отдельно учим модель Свойство → Преимущество → Выгода и связываем её с болью клиента.

🤝 Встреча — отдельная страница

Возражения не смешиваем со встречей. Встреча ведётся по диагностической логике.

Маршрут встречи

1. Приветствие

Знакомство → ТМР → озвучить план.

2. Диагностика по СПИН

С → П → И → Н. Не перескакиваем и не показываем весь функционал.

3. СПВ

Показываем только функции, которые закрывают найденную боль.

4. Ценность

Собираем результат для клиента.

5. Цена / следующий шаг

Переходим после того, как ценность понятна.

Переход из СПИН в СПВ

Если клиент сказал проблему → выяснили последствия → получили желаемый результат. Теперь функция должна отвечать именно на эту цепочку.

🛡 Возражения — отдельная страница
